title: GitHub integration
description: Wire the packaged TypeScript GitHub catalog with a repository allowlist, lazy credentials, read-only tool exposure, and explicit lifecycle ownership.

`@kaji/sdk/integrations/github` is an experimental TypeScript package subpath
for bounded GitHub evidence and issue mutations. It uses a fixed
`https://api.github.com` origin, rejects redirects, validates repository names
against an application-owned allowlist before reading credentials, and adds its
own stable request identity headers.

## Read-only investigation agent

Install `@kaji/sdk`, `zod`, your provider SDK, and `@dotenvx/dotenvx`, then put
`OPENAI_API_KEY` and a fine-grained `GITHUB_TOKEN` in an encrypted or ignored
environment file. Replace `owner/repo` with every exact repository the agent may
read.

<!-- docs-test:github-read-only:start -->
```ts
import { AgentBuilder, OpenAIProvider, deadlineAfter } from "@kaji/sdk";
import { createGithubIntegration } from "@kaji/sdk/integrations/github";

const principalId = "github-investigator";
const github = createGithubIntegration({
  repositories: ["owner/repo"],
  toolExposure: "read-only",
  tokenFor: async (context) => {
    if (context.signal.aborted) throw context.signal.reason;
    if (context.principalId !== principalId) throw new Error("GitHub credential unavailable");
    const token = process.env.GITHUB_TOKEN;
    if (!token) throw new Error("GITHUB_TOKEN is required");
    return token;
  },
});

try {
  const runtime = new AgentBuilder()
    .provider(new OpenAIProvider({ apiKey: process.env.OPENAI_API_KEY! }))
    .integration(github)
    .defaultContext({ principalId })
    .systemPrompt("Use GitHub evidence from owner/repo and cite immutable refs.")
    .build();

  try {
    const result = await runtime.turn("Inspect the latest failed checks.", {
      context: { deadlineAtMs: deadlineAfter(30_000) },
    });
    console.log(result.text);
  } finally {
    try {
      const unsettledTools = await runtime.drainTools(10_000);
      const unsettledProviders = await runtime.drainProviders(10_000);
      if (unsettledTools.length > 0 || unsettledProviders.length > 0) {
        throw new Error("Kaji shutdown did not settle");
      }
    } finally {
      runtime.close();
    }
  }
} finally {
  github.close();
}
```

`tokenFor` is lazy and receives the complete `ToolExecutionContext`. Return the
raw token; Kaji validates it and adds the authorization scheme. Repository
policy and argument validation run before the callback, so a disallowed
repository does not trigger credential lookup. The allowlist is exact and
case-sensitive.

`toolExposure: "read-only"` filters tools before registration, so mutation
schemas are not sent to the model. This is a model-exposure boundary, not a token
permission boundary. Use a fine-grained token limited to the selected
repositories and only the read permissions required for Contents, Issues, Pull
requests, Checks, Actions, and Deployments.

## Tool catalog

Read-only exposure registers these 13 parallel-safe tools with 10-second tool
deadlines:

- `get_file`, `get_issue`, `list_issues`, and `search_code`;
- `get_commit`, `get_pull_request`, and `list_pull_request_files`;
- `list_check_runs`, `get_workflow_run`, and `list_workflow_jobs`;
- `list_file_commits`, `get_release`, and `list_deployments`.

The compatibility default, `toolExposure: "all"`, additionally exposes
`create_issue` and `add_comment`. Both are serialized `external_effect` tools
with 15-second tool deadlines. External effects do not require approval by
default: configure a `ToolPolicy` that requires approval for
`external_effect`, install an approval handler, and use a token with the needed
write permission before choosing `"all"`. A connection loss after mutation
dispatch is an unknown outcome; reconcile the issue or comment marker before
retrying.

## Lifecycle and observability

`AgentBuilder` registers an integration but does not own or close it. Drain
provider and tool work, confirm that no unsettled IDs remain, close the runtime,
then call `github.close()`. Closing the integration is idempotent.

If the application uses metrics or trace sinks, pass the same sinks to both the
builder and `createGithubIntegration`; builder configuration does not
automatically flow into the integration requester.

## Current limits

The package is deliberately bounded:

- list operations return at most 20 items per page and do not auto-paginate;
- file content over 48 KiB is omitted, and returned content must decode as UTF-8;
- raw Actions logs, GraphQL, blame, GitHub Enterprise Server, arbitrary HTTP,
  and unbounded results are not supported;
- the SDK does not read `GITHUB_TOKEN` automatically and does not exchange
  GitHub App, OAuth, or installation credentials; the application owns
  `tokenFor`;
- the package remains experimental until the protected keyed API and release
  evidence gates pass.
