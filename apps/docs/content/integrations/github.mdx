title: GitHub integration
description: The packaged TypeScript GitHub integration is removed with the capability cut; the Python beta catalog retains the GitHub tool subset.
---

The packaged TypeScript GitHub integration (`@irogane/kaji/integrations/github`)
was removed with the TypeScript capability cut. The retained TypeScript product
is the one-shot `Kaji.execute` capability surface: it ships no integration
runtime, no `kaji add` command, and no provider adapters.

The Python package keeps the beta GitHub catalog: a repository allowlist, lazy
credentials, read-only tool exposure, and explicit lifecycle ownership. Copy
the bundle with the Python CLI:

{/* docs-test:github-read-only:start */}

```bash
python -m kaji.cli add github --out ./integrations/github
```

{/* docs-test:github-read-only:end */}

Credentials stay lazy and application-owned: the runtime validates repository
names against the allowlist before reading `GITHUB_TOKEN`, and a disallowed
repository never triggers credential lookup. The client is fixed to
`https://api.github.com`, rejects redirects, bounds response headers and
bodies, and treats a connection loss after mutation dispatch as an unknown
outcome.

Failure recovery is pinned by the
[integration recovery contract](/docs/integrations/recovery-v1):
`INTEGRATION_AUTH_REQUIRED` maps `github_token_missing` to
`CONFIGURE_GITHUB_TOKEN` and
https://kaji.dev/docs/integrations/recovery-v1#github-token.
