The TypeScript SDK supports packaged integration subpaths and source-owned
registry bundles. Import a packaged subpath directly, or use `kaji add` to copy
the files declared by a registry manifest plus a provenance sidecar into your
project. Review copied code before registering it with `AgentBuilder`. Kaji
never activates catalog tools implicitly.

## Catalog status

This is the catalog in TypeScript `0.2.0-beta.10` and Python `0.2.0b1`.
WIP entries whose registry tier is `experimental` require
`--allow-experimental` and are outside the stable beta set.

| Integration | Support status | Runtime            | Auth                    | Tools                     |
| ----------- | -------------- | ------------------ | ----------------------- | ------------------------- |
| `echo`      | Beta           | Python, TypeScript | None                    | 2                         |
| `github`    | Beta           | Python, TypeScript | Application-owned token | 6 copied / 15 packaged TS |

The TypeScript and Python registries contain only `echo` and `github`. Their
manifests and JSON schemas are validated, and shared entries are checked for
cross-SDK ABI parity. Source modules outside this index are not discoverable or
installable catalog entries.

## Discover and copy

After [installing the TypeScript beta](/docs/install#typescript), use its local
`kaji` binary:

```bash
npm exec -- kaji list-integrations
npm exec -- kaji add echo --out ./integrations/echo
npm exec -- kaji add github --out ./integrations/github
```

Use `--check` to inspect copy status without writing and `--json` for tooling.
A matching unmodified bundle is a no-op. `--force` replaces only an unmodified,
same-provider outdated bundle; it does not overwrite arbitrary local edits.
The Python SDK exposes the same copy workflow through its own `kaji` binary.

## GitHub

The copied GitHub bundle exposes four parallel-safe reads:
`get_file`, `get_issue`, `list_issues`, and `search_code`; and two serialized
external effects: `create_issue` and `add_comment`. The integration namespace
is applied before provider dispatch.

The TypeScript package also exports `kaji-sdk/integrations/github`. Its catalog
adds nine bounded evidence reads for commits, pull requests, check runs, Actions
workflow runs and jobs, file history, releases, and deployments. Use
`toolExposure: "read-only"` to register only the 13 read tools; the compatibility
default is the complete 15-tool catalog.

The runtime requires an application-owned repository allowlist and invokes the
application's `tokenFor` callback per tool execution context. Its client is
fixed to `https://api.github.com`, rejects redirects, bounds response headers
and bodies, and treats a connection loss after mutation dispatch as an unknown
outcome. Include an application-owned marker in the issue title or body and
reconcile that marker before retrying. Kaji does not send its internal
idempotency key to GitHub.

GitHub's machine registry tier is `beta`. Local package and ABI checks do not
establish protected keyed-API or release evidence.

See the [GitHub integration guide](/docs/integrations/github) for package wiring,
token ownership, lifecycle, permissions, limits, and unsupported surfaces.

## Gmail status

No Gmail manifest, client, or tool bundle is shipped in either registry. The
SDKs contain shared Google OAuth, macOS Keychain, fixed-origin, and
recovery-contract primitives. Those primitives, together with the presence of
`connect` and `disconnect` commands, do not make `kaji add gmail` or
`kaji connect gmail` valid.

See [integration recovery](/docs/integrations/recovery-v1) for the closed error
vocabulary, including the Gmail rows reserved by the shared contract.
