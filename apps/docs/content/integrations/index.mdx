Integration catalog ownership now sits with the Python SDK. The retained
TypeScript capability product is the one-shot `Kaji.execute` surface: it ships
no integration runtime, no packaged integration subpaths, and no
`add`/`connect`/`list-integrations` CLI commands. Use `kaji add` from the
Python SDK to copy the files declared by a registry manifest plus a provenance
sidecar into your project. Review copied code before registering it. Kaji
never activates catalog tools implicitly.

## Catalog status

This is the catalog in the TypeScript `0.3.0-alpha.1` candidate and Python
`0.2.0b1`. All current catalog entries are beta. Future entries marked
`experimental` require `--allow-experimental`.

| Integration | Support status | Runtime            | Auth                    | Tools |
| ----------- | -------------- | ------------------ | ----------------------- | ----- |
| `echo`      | Beta           | Python | None                    | 2     |
| `gmail`     | Beta           | Python | Google OAuth grant      | 3     |
| `github`    | Beta           | Python | Application-owned token | 6     |

The Python registry contains `echo`, `gmail`, and `github`. Its manifests and
JSON schemas are validated. The TypeScript package ships no integration
implementation. Source modules outside this index are not discoverable or
installable catalog entries.

The **Runtime** column lists the runtimes recorded by the registry catalog, not
where it is published. The TypeScript package is a local alpha candidate; the
Python package's publication to PyPI is deferred, so `Python` here means the
in-repo implementation exists and passes cross-SDK parity, not that a
`pip install` is available yet.

## Discover and copy

With the Python SDK's local `kaji` binary:

```bash
python -m kaji.cli list-integrations
python -m kaji.cli add echo --out ./integrations/echo
python -m kaji.cli add github --out ./integrations/github
python -m kaji.cli add gmail --out ./integrations/gmail
```

Use `--check` to inspect copy status without writing and `--json` for tooling.
A matching unmodified bundle is a no-op. `--force` replaces only an unmodified,
same-provider outdated bundle; it does not overwrite arbitrary local edits.

## GitHub

The copied GitHub bundle exposes four parallel-safe reads:
`get_file`, `get_issue`, `list_issues`, and `search_code`; and two serialized
external effects: `create_issue` and `add_comment`. The integration namespace
is applied before tool dispatch.

The runtime requires an application-owned repository allowlist and invokes the
application's `token_for` callback per tool execution context. Its client is
fixed to `https://api.github.com`, rejects redirects, bounds response headers
and bodies, and treats a connection loss after mutation dispatch as an unknown
outcome. Include an application-owned marker in the issue title or body and
reconcile that marker before retrying. Kaji does not send its internal
idempotency key to GitHub.

GitHub's machine registry tier is `beta`. Local package and ABI checks do not
establish protected keyed-API or release evidence.

See the [GitHub integration guide](/docs/integrations/github) for token
ownership, lifecycle, permissions, limits, and unsupported surfaces.

## Gmail

The copied Gmail bundle exposes two parallel-safe reads, `list_messages` and
`get_message`, and one serialized external effect, `send_message`. The
integration namespace is applied before tool dispatch.

Gmail authenticates with a Google OAuth grant rather than a static token. Run
`kaji connect gmail --principal <id>` to store a refresh grant, then wire the
integration's Python `token_for` callback to the OAuth client's access-token
accessor. The scopes are `gmail.readonly` and `gmail.send`. Its client is fixed
to `https://gmail.googleapis.com`, rejects redirects, bounds response headers
and bodies, decodes base64url message payloads, and treats a connection loss
after send dispatch as an unknown outcome.

Gmail's registry tier is `beta`, so `kaji add gmail` does not require
`--allow-experimental`. Its live send path is an external-effect boundary;
reconcile a message before retrying an ambiguous send. Local package and ABI
checks do not establish provider or release evidence.

See [integration recovery](/docs/integrations/recovery-v1) for the closed error
vocabulary, including the Gmail rows.
