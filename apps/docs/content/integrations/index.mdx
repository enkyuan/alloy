Kaji supports source-owned registry bundles and selected packaged subpaths.
`kaji add` copies a manifest, implementation, fixtures, and any included tests
into your project. Review the copy, configure its dependencies and credentials,
then register the integration with `AgentBuilder`. A packaged subpath is imported
directly instead. Kaji does not silently activate catalog tools.

## Catalog status

This is the 0.2 beta-candidate catalog. “Experimental” entries require
`--allow-experimental` and are outside the first beta compatibility promise.

| Integration | Stability    | Runtime            | Auth                    | Tools                     |
| ----------- | ------------ | ------------------ | ----------------------- | ------------------------- |
| `echo`      | Beta         | Python, TypeScript | None                    | 2                         |
| `github`    | Experimental | Python, TypeScript | Application-owned token | 6 copied / 15 packaged TS |

The Python and TypeScript registries currently contain only `echo` and
`github`. Their manifests and JSON schemas are validated, and the shared entries
are checked for cross-SDK ABI parity. Source modules outside this index are not
discoverable or installable catalog entries.

## Discover and copy

<Tabs items={["python", "typescript"]}>
  <Tab value="python">
    ```bash
    kaji list-integrations
    kaji add echo --out ./integrations
    kaji add github --out ./integrations --allow-experimental
    ```

  </Tab>
  <Tab value="typescript">
    ```bash
    npx --package=@kaji/sdk kaji list-integrations
    npx --package=@kaji/sdk kaji add echo --out ./integrations
    npx --package=@kaji/sdk kaji add github --out ./integrations --allow-experimental
    ```

  </Tab>
</Tabs>

Use `--check` to inspect copy status without writing and `--json` for tooling.
A current unmodified bundle is a no-op. `--force` replaces only an unmodified,
same-provider outdated bundle; it does not overwrite arbitrary local edits.

## GitHub

The copied experimental GitHub bundle exposes four parallel-safe reads:
`get_file`, `get_issue`, `list_issues`, and `search_code`; and two serialized
external effects: `create_issue` and `add_comment`. The integration namespace
is applied before provider dispatch.

The TypeScript package also exports `@kaji/sdk/integrations/github`. Its catalog
adds nine bounded evidence reads for commits, pull requests, check runs, Actions
workflow runs and jobs, file history, releases, and deployments. Use
`toolExposure: "read-only"` to register only the 13 read tools; the compatibility
default is the complete 15-tool catalog.

The runtime requires an application-owned repository allowlist and invokes the
application's `tokenFor` callback per tool execution context. Its client is fixed to
`https://api.github.com`, rejects redirects, bounds response headers and bodies,
and treats a connection loss after mutation dispatch as an unknown outcome.
Reconcile the issue or comment marker before retrying such a mutation.

GitHub has deterministic package and ABI proofs, but it remains experimental
until protected keyed API evidence and the release gates complete.

See the [GitHub integration guide](/docs/integrations/github) for package wiring,
token ownership, lifecycle, permissions, limits, and unsupported surfaces.

## Gmail status

No Gmail manifest, client, or tool bundle is shipped in either registry at this
checkpoint. The SDKs contain shared Google OAuth, macOS Keychain, fixed-origin,
and recovery-contract primitives for a future Gmail integration. Those
primitives -- and the presence of `connect` / `disconnect` commands -- do not make
`kaji add gmail` or `kaji connect gmail` valid today.

See [integration recovery](/docs/integrations/recovery-v1) for the closed error
vocabulary, including the Gmail rows reserved by the shared contract.
