title: Reference Service
description: The WIP kaji-serve package exposes a FastAPI and Soniox STT edge outside the supported 0.2 SDK beta.
---

`kaji-serve` (`kaji/serve`) exposes one FastAPI process with REST routes and a
Soniox speech-to-text WebSocket on port 8080. It is a WIP reference edge, not
part of the 0.2 SDK beta core or a production durability or horizontal-scaling
claim.

The STT socket authenticates the caller, accepts audio frames, and returns
partial, final, and complete transcripts. It does not queue an agent command,
run `AgentRuntime`, relay an agent response, or synthesize speech. Applications
own the explicit hand-off from a final transcript to the embedded SDK runtime.

## Run with docker compose

Compose starts the API and its Postgres/Supabase dependencies. Copy the
environment template and replace every `CHANGE_ME` value before non-local use:

```bash
cd docker/kaji
cp .env.example .env
docker compose up
```

The `api` is reachable at `http://localhost:8080`. Health check:

```bash
curl http://localhost:8080/health
```

## Run directly

If its dependencies are already available, start the single API process:

```bash
cd kaji/serve
uv sync
uv run uvicorn kaji_serve.server.app:app --host 0.0.0.0 --port 8080
```

## When to use the reference service

Use it only to evaluate:

- the FastAPI service shell,
- real-time Soniox transcription over a WebSocket,
- the present service boundary before supplying production persistence and
  coordination.

For agent execution and embedded apps, use the SDK directly. `kaji-serve` does
not wire an `AgentRuntime` adapter, a persistent Kaji event store, restart-safe
effect idempotency, or distributed same-session coordination. See the
[SDK overview](/docs).
