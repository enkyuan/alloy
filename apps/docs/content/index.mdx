Kaji is an embeddable TypeScript SDK for building agents. Compose a provider,
tools, and policy in your application, then run the model/tool loop in process.
The core needs no database, server, or control plane.

## Packages

| Package             | Path                  | What it is                                        |
| ------------------- | --------------------- | ------------------------------------------------- |
| `kaji`              | `kaji/packages/ts`    | TypeScript SDK and the primary path in these docs |
| `kaji` (Python)     | `kaji/packages/py`    | Python SDK with shared event and tool contracts   |
| `@irogane/kaji/cli` | `apps/cli`            | WIP cross-language scaffold and diagnostics       |
| `kaji-serve`        | `kaji/packages/serve` | WIP REST and Soniox STT reference service         |

The primary TypeScript package is currently available only as the local
`./irogane-kaji-0.3.0-alpha.1.tgz` release candidate. Python remains a
source-checkout compatibility path while PyPI publication is deferred.

## Start in process

| If you want…                                  | Use                     |
| --------------------------------------------- | ----------------------- |
| In-process agent in a Node or Bun application | `kaji`                  |
| Deterministic provider tests without API keys | `@irogane/kaji/testing` |
| WIP REST or transcription over WebSocket      | `kaji-serve`            |

Use the [reference service](/docs/reference-service) only to evaluate the WIP
Python REST and Soniox STT service.

## Core model

`AgentBuilder` composes a model provider, risk-classified tools, and an optional
policy. `AgentRuntime.turn()` records the user message, calls the provider,
validates selected tools, and returns the final text with the events produced
by that turn. The default store and committer are bounded, in-memory, and
process-local.

Start with `MockProvider` from `@irogane/kaji/testing` to verify the local runtime.
OpenAI is the recommended live-provider path for this TypeScript candidate.
The `echo`, `gmail`, and `github` catalog entries are beta; the packaged GitHub
TypeScript subpath remains experimental. Catalog tools are never activated
implicitly.

## Python compatibility

The TypeScript and Python SDKs validate the same v1 event schema. The Python
package also contains WIP RAG, voice, and Redis surfaces. Those extras are not
part of the TypeScript SDK or the documented TypeScript candidate path.

See [integrations](/docs/integrations) for the exact catalog and stability
boundaries.
