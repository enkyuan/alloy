---
title: Getting Started
description: Install kaji, define a tool, and run an agent turn end-to-end. Python and TypeScript.
---

This page takes you from `install` to a working agent in five steps. By the
end you'll have sent a user message and received a model response, with one
tool wired in.

<Steps>
  <Step>
    ### Install

    <Tabs items={["python", "typescript"]}>
      <Tab value="python">
        ```bash
        pip install "kaji[openai]"
        ```
      </Tab>
      <Tab value="typescript">
        ```bash
        bun add @kaji/sdk openai
        ```
      </Tab>
    </Tabs>

    These pull the SDK plus one provider client. For other providers or
    optional extras, see [install](/docs/install).

  </Step>

  <Step>
    ### Set a provider key

    Pick one provider and export its key. The base SDK uses a mock provider for
    tests until you configure a real one; scaffolds generated with
    `--provider openai` set `KAJI_MODEL_PROVIDER=openai`.

    ```bash
    export OPENAI_API_KEY=sk-...        # or
    export ANTHROPIC_API_KEY=sk-ant-... # or
    export KIMI_API_KEY=...              # Kimi/OpenRouter
    ```

    To choose another provider, set `KAJI_MODEL_PROVIDER=openai`,
    `anthropic`, `gemini`, or `kimi`.

  </Step>

  <Step>
    ### Define a tool

    Tools are a spec (name, description, JSON-schema parameters) plus a
    handler. The `@function_tool` decorator (Python) / `functionTool(...)`
    helper (TS) derives the spec from type hints and the docstring.

    <Tabs items={["python", "typescript"]}>
      <Tab value="python">
        ```python
        from kaji import function_tool

        @function_tool
        async def get_weather(city: str) -> dict:
            """Look up the weather for a city."""
            return {"city": city, "tempF": 68}
        ```
      </Tab>
      <Tab value="typescript">
        ```ts
        import { functionTool } from "@kaji/sdk";
        import { z } from "zod";

        const getWeather = functionTool(
          {
            name: "get_weather",
            description: "Look up the weather for a city.",
            parameters: z.object({ city: z.string() }),
          },
          async ({ city }) => ({ city, tempF: 68 }),
        );
        ```
      </Tab>
    </Tabs>

  </Step>

  <Step>
    ### Build the runtime

    `AgentBuilder` wires a provider, tools, and an in-memory bus + store into
    a runnable `AgentRuntime`.

    <Tabs items={["python", "typescript"]}>
      <Tab value="python">
        ```python
        from kaji import AgentBuilder, get_provider

        runtime = (
            AgentBuilder()
            .provider(get_provider("openai"))
            .tool(get_weather)
            .system_prompt("You are a helpful assistant.")
            .build()
        )
        ```
      </Tab>
      <Tab value="typescript">
        ```ts
        import { AgentBuilder, OpenAIProvider } from "@kaji/sdk";

        const runtime = new AgentBuilder()
          .provider(new OpenAIProvider({ apiKey: process.env.OPENAI_API_KEY! }))
          .tool(getWeather)
          .systemPrompt("You are a helpful assistant.")
          .build();
        ```
      </Tab>
    </Tabs>

    No DB. No server. The runtime holds an in-memory event store
    (`InMemoryEventStore`) and bus (`InMemoryEventBus` in Python,
    `EventBus` in TS) by default.

  </Step>

  <Step>
    ### Run a turn

    `turn()` appends the user message, runs one model/tool loop, and returns
    the final assistant text. The model decides whether to call your tool; the
    runtime dispatches it, collects the result, and produces a response.

    <Tabs items={["python", "typescript"]}>
      <Tab value="python">
        ```python
        import asyncio

        async def main():
            result = await runtime.turn("What's the weather in NYC?")
            print(result.text)

        asyncio.run(main())
        ```
      </Tab>
      <Tab value="typescript">
        ```ts
        const result = await runtime.turn("What's the weather in NYC?");
        console.log(result.text);
        ```
      </Tab>
    </Tabs>

    To stream events as they happen instead of reading them after the turn,
    subscribe to the bus. See [event bus](/docs/concepts/event-bus).

  </Step>
</Steps>
