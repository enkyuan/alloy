title: Getting Started
description: Prepare the Kaji TypeScript beta from source, define a typed tool, and inspect an agent turn end to end.
---

This tutorial builds one TypeScript agent in six steps. You will first verify
the runtime without credentials, then configure OpenAI and a risk-classified
tool.

<Steps>
  <Step>
    ### Prepare the source checkout

    ```bash
    git clone https://github.com/enkyuan/alloy.git
    cd alloy
    bun install --frozen-lockfile
    ```

    TypeScript `0.2.0-beta.10` is the protected npm release candidate, but the
    public registry command remains unavailable until registry-byte
    verification succeeds. Python wheel and PyPI publication are deferred for
    this release. You do not need a provider key for the first run.

  </Step>

  <Step>
    ### Verify the local runtime

    Start with the deterministic mock provider. This separates package and
    runtime setup from network and credential failures.

    {/* getting-started:no-key:typescript:start */}
    ```ts
    import { AgentBuilder } from "kaji-sdk";
    import { MockProvider } from "kaji-sdk/testing";

    const runtime = new AgentBuilder().provider(new MockProvider()).build();
    const result = await runtime.turn("Say hello.");
    console.log(result.text);
    ```
    {/* getting-started:no-key:typescript:end */}

    Save the example as `kaji.mts`, then run it:

    ```bash
    bun kaji.mts
    ```

    It prints `The mock provider has completed the tool loop.`

    The Python distribution is unavailable from PyPI for this release. From a
    [source checkout](/docs/install#source-checkout), the same no-key proof
    keeps risk and caller identity explicit. `AgentBuilder` wires a provider
    and tools to the runtime's event journal:

    {/* getting-started:no-key:python:start */}
    ```python
    import asyncio

    import kaji


    @kaji.function_tool(description="Return a local status.", risk="read")
    async def local_status() -> dict:
        return {"status": "ready"}


    async def main() -> None:
        runtime = (
            kaji.AgentBuilder()
            .provider(kaji.get_provider("mock", reply="mock"))
            .tool(local_status)
            .default_context(kaji.TurnContext(principal_id="docs-source"))
            .build()
        )
        try:
            result = await runtime.turn("Say hello.")
            print(result.text)
        finally:
            runtime.close()


    asyncio.run(main())
    ```
    {/* getting-started:no-key:python:end */}

    Save the Python example as `kaji/smoke.py`, then run it:

    ```bash
    uv sync --project kaji
    uv run --project kaji python kaji/smoke.py
    ```

  </Step>

  <Step>
    ### Configure OpenAI

    Add the beta-supported OpenAI peer, then export its credential before
    running the live-provider example:

    ```bash
    bun add "openai@>=4 <8"
    export OPENAI_API_KEY=sk-...
    ```

    The `openai()` provider factory reads `OPENAI_API_KEY`. Load the variable
    with your application's environment tooling. OpenAI is the stable
    live-provider adapter in the npm/TypeScript beta contract. Anthropic,
    Gemini, Kimi, and OpenRouter are implemented but remain WIP; their machine
    contract tier is `experimental`.

  </Step>

  <Step>
    ### Define a typed tool

    A tool combines a model-visible description, a Zod parameter schema, an
    explicit risk classification, and a handler. Create `agent.mts`:

    ```ts
    import { AgentBuilder, deadlineAfter, functionTool, openai } from "kaji-sdk";
    import { z } from "zod";

    const getWeather = functionTool(
      {
        name: "get_weather",
        description: "Look up the weather for a city.",
        parameters: z.object({ city: z.string() }),
        risk: "read",
      },
      async ({ city }, context) => ({
        city,
        tempF: 68,
        principal: context.principalId,
      }),
    );
    ```

    Kaji validates model-generated arguments against the Zod schema before the
    handler runs.

  </Step>

  <Step>
    ### Build the runtime

    Continue in `agent.mts`. `AgentBuilder` makes the provider and
    available tools explicit:

    ```ts
    const runtime = new AgentBuilder()
      .provider(openai())
      .tool(getWeather)
      .systemPrompt("You are a helpful weather assistant.")
      .build();
    ```

    No database or server is required. The default event store and committer
    are bounded, in-memory, and process-local.

  </Step>

  <Step>
    ### Run a turn

    Tool-capable turns require a caller principal. Add a deadline so the caller
    can tighten the runtime's whole-turn limit:

    ```ts
    try {
      const result = await runtime.turn("What's the weather in Chicago?", {
        context: {
          principalId: "weather-app",
          deadlineAtMs: deadlineAfter(30_000),
        },
      });
      console.log(result.text);
    } finally {
      runtime.close();
    }
    ```

    Run the completed example from the repository root:

    ```bash
    bun kaji/ts/agent.mts
    ```

    `turn()` records the user message, calls the provider, validates and
    dispatches any selected tool, and returns the final assistant text.
    `deadlineAfter()` converts a duration to the absolute epoch value expected
    by `deadlineAtMs`.

  </Step>
</Steps>

## Using Python?

The Python SDK implements the shared event and tool contracts, but it is not
the primary path in this tutorial. The distribution is not available from
PyPI for this release. See the [Python source setup](/docs/install#python-sdk)
for Python-specific commands.
