---
title: Runtime
description: AgentBuilder configures the runtime; AgentRuntime.turn runs the high-level user-message path; AgentRuntime.history reads a bounded cursor page of stored events.
---

`AgentRuntime` is the loop that takes a user message, calls the LLM,
validates and dispatches tool calls, and projects stored events into session
state. Tool calls are sequential unless their specs explicitly opt into
parallel-safe execution; even then, the default concurrency limit is four. You
compose a TypeScript runtime with `AgentBuilder`.

## AgentBuilder

| Method                         | Description                                                                                                                    |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `.provider(provider)`          | Sets the model provider. Required before `build()`.                                                                            |
| `.tool(tool)`                  | Adds one function tool. Call it again to add more.                                                                             |
| `.integration(value)`          | Adds an integration that registers a scoped bundle of tools.                                                                   |
| `.systemPrompt(prompt)`        | Sets the instruction sent with provider requests.                                                                              |
| `.strategy(strategy)`          | Overrides loop behavior such as maximum iterations.                                                                            |
| `.policy(policy)`              | Adds risk-based tool approval policy.                                                                                          |
| `.defaultContext(context)`     | Sets an explicit single-tenant default. Prefer per-turn identity in multi-tenant hosts.                                        |
| `.toolExecutionLimits(limits)` | Overrides bounded tool execution.                                                                                              |
| `.build(options)`              | Creates a runtime with a bounded in-memory store and atomic committer unless the application supplies its own implementations. |

## AgentRuntime

| Method                              | Returns               | Description                                                                                         |
| ----------------------------------- | --------------------- | --------------------------------------------------------------------------------------------------- |
| `turn(text, options)`               | `Promise<TurnResult>` | Runs one user message through the model/tool loop.                                                  |
| `send(sessionId, text, options)`    | `Promise<void>`       | Appends a user message to a known session and runs one turn.                                        |
| `history(sessionId, cursorOptions)` | stored-event page     | Returns events after the supplied sequence cursor in append order; the default page limit is 1,024. |

## Example

```ts
import { AgentBuilder, openai } from "kaji-sdk";

const runtime = new AgentBuilder()
  .provider(openai())
  .systemPrompt("You are a helpful assistant.")
  .build();

const result = await runtime.turn("Hello");
console.log(result.text);
```

See [event delivery](/docs/concepts/event-bus) for the underlying mechanism.

## Ordering and execution context

Turns for the same session serialize FIFO within the process-local coordinator;
different sessions may run concurrently. Persisted `sequence`, not timestamp,
defines event order. Page history with `afterSequence` and resume subscriptions
from the last stored sequence.

A text-only runtime may omit a principal. Once enabled tools are present, pass
`{ context: { principalId: ... } }` to `turn()`. Kaji resolves that
caller-owned input into a detached, validated, readonly `ToolExecutionContext`
for each handler; metadata is recursively frozen. The snapshot includes
correlation IDs, the canonical idempotency key, deadline, and cancellation
signal. Handlers must not replace identity or correlation fields.

The Python SDK follows the same lifecycle with snake_case configuration and
context fields, including `system_prompt`, `default_context`,
`tool_execution_limits`, and `principal_id`.
