---
title: Tool Registry
description: Register a risk-classified tool as a spec plus a handler, then execute it with explicit caller context.
---

Reach for the tool registry to expose functions your agent can call. The
runtime sends the full spec list to the model each turn, dispatches whatever
the model picks, and validates each call before approval or execution. Calls
run sequentially by default. Set `parallel_safe: true` only for
effect-independent tools; the runtime then permits at most four handlers to
run at once by default.

The shortest TypeScript path is `functionTool(...)`, which derives the JSON
Schema contract from Zod:

```ts
import { functionTool } from "kaji-sdk";
import { z } from "zod";

const getWeather = functionTool(
  {
    name: "get_weather",
    description: "Look up the weather for a city.",
    parameters: z.object({ city: z.string() }),
    risk: "read",
  },
  async ({ city }, context) => ({
    city,
    tempF: 68,
    principal: context.principalId,
  }),
);
```

Pass tools to the runtime via `AgentBuilder().tool(...)`. For direct registry
use, register a `ToolSpec` and handler on `ToolRegistry`. To bind a hand-written
spec to `AgentBuilder`, provide an integration whose `register(registry)`
method registers the spec, then pass it to `.integration(...)`.

Every enabled spec requires one closed risk value: `read`, `write`,
`external_effect`, `destructive`, or `admin`. A runtime turn that
can execute a tool also requires `TurnContext.principalId`. Missing risk or
identity fails before the handler starts.

Handlers receive a detached, validated, readonly `ToolExecutionContext`; its
metadata is recursively frozen. It carries the principal, session, turn,
request, trace, tool-call, idempotency, deadline, cancellation, metadata, and
optional application-owned `db` values. TypeScript function and integration
handlers use `(args, context)`, and the direct registry executor order is
`(toolName, toolArgs, context)`.

Timeout or cancellation after a handler starts can have an unknown external
outcome. Reconcile with `context.idempotencyKey` before deciding to retry the
effect.

The Python SDK exposes the same contract through `@function_tool`,
`register_tool`, `principal_id`, and `idempotency_key`; Python integration
handlers receive `(context, args)`.
