Pick a provider when you build the runtime. The runtime never imports
provider-specific types: translation happens at the provider boundary
against a neutral message and tool-spec format.

| `mock`      | Removed (capability cut)      | Main package   | Testing only | -                    |

The TypeScript capability product is the one-shot `Kaji.execute` surface: it
ships no provider factories, no `ModelProvider` interface, and no
`MockProvider`. Live providers are a Python path: select one explicitly with
`get_provider(name)` or a constructed provider passed to
`AgentBuilder.provider(...)`. Call `register_provider` only when you also want
name-based lookup through `get_provider`. OpenAI is the only primary provider
path documented for the local `0.3.0-alpha.1` candidate; other implemented
adapters remain WIP.

Kimi reuses the OpenAI-compatible transport and does not expose native vendor
features; it requires an explicit `api_key` or `OPENROUTER_API_KEY`. Gemini
falls back to `GOOGLE_API_KEY`.

## Custom-provider cancellation contract

Custom providers are cooperative in-process boundaries. While opening a
request and while streaming, they must observe the runtime-provided
`cancellation_token`, stop the underlying request, and let the stream iterator
settle when cancellation is requested. They must also support the runtime
closing that iterator after partial output.

If a provider remains active beyond the configured cancellation grace, Kaji
raises `PROVIDER_CANCELLATION_CONTRACT_VIOLATION` and quarantines that session
until `drain_providers()` confirms settlement. Closing the runtime rejects new
turns; it cannot force-kill hostile in-process code. Run the same
cancellation-contract suite used by the built-in adapters before describing a
custom provider as production-safe.

## TTS and STT

TTS providers (`gemini`, `openai`, `none`) implement `TTSProvider` as a WIP
Python SDK modality. The separate WIP `kaji-serve` STT WebSocket forwards audio
to Soniox when `SONIOX_API_KEY` is configured. Neither surface is part of the
TypeScript candidate's documented provider path. The reasoning loop itself
remains modality-agnostic.

The Python SDK uses the snake_case cancellation names `cancellation_token` and
`drain_providers()`.
