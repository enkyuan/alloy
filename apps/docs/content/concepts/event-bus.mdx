---
title: Event Delivery
description: Subscribe through the TypeScript event committer for gap-free process-local delivery; split event-bus adapters are WIP compatibility surfaces.
---

Subscribe to the canonical append-and-delivery boundary when you want to push
agent deltas to a UI or consume a resumable event stream. TypeScript calls this
boundary an `EventCommitter`.

The default builder creates `InMemoryEventCommitter`. It commits to an
`EventStore` and attaches bounded per-session subscribers through one gap-free
process-local boundary.

{/* event-delivery:typescript:start */}

```ts
import { AgentBuilder, InMemoryEventCommitter } from "kaji";
import { MockProvider } from "kaji/testing";

const sessionId = "session-1";
const committer = new InMemoryEventCommitter();
const runtime = new AgentBuilder()
  .provider(new MockProvider({ reply: "Hello" }))
  .build({ committer });
const subscription = committer.subscribe(sessionId, { afterSequence: 0 });

const turn = runtime.turn("Hello", { sessionId });
try {
  for await (const event of subscription) {
    console.log(event.sequence, event.type);
    if (event.type === "agent.message.completed") break;
  }
} finally {
  await subscription.return();
}
await turn;
runtime.close();
```

{/* event-delivery:typescript:end */}

Resume strictly after the last persisted cursor with `afterSequence`. A
subscriber queue holds 1,024 events by default and raises
`EventBufferOverflowError` instead of silently dropping history. When the
consumer stops, break out of `for await` or call the subscription's `return()`
method so it detaches.

`EventBus` / `InMemoryEventBus` and the split journal/committer adapters remain
WIP compatibility surfaces for deployments that cannot share one atomic
boundary. Split persistence and publication expose delivery failures and
pending-event recovery to the host. Production replay needs an
application-owned persistent `EventStore`; the TypeScript beta ships no
persistent store or distributed coordinator.

The Python equivalent is `EventJournal` /
`InMemoryEventJournal`, with `after_sequence` cursors. Its optional Redis
event bus provides cross-process stream delivery, but it is not an
`EventStore`; canonical replay still depends on the application's event store.
