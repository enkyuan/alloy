---
title: Install
description: Install kaji in Python or TypeScript, pick the provider extras you need, and learn the v0.x compatibility policy.
---

Kaji ships as two SDKs that share the stable-core wire format. The current
release candidates are Python `0.2.0b1` and TypeScript `0.2.0-beta.3`. They are
not promotable beta releases until the protected release evidence passes. All
`0.x` releases are pre-1.0, so pin exact versions in production.

## Python

```bash
pip install "kaji-sdk[openai]==0.2.0b1"    # beta-supported provider
pip install "kaji-sdk[anthropic]==0.2.0b1" # experimental/WIP adapter
pip install "kaji-sdk[providers]==0.2.0b1" # all optional provider clients
```

The PyPI distribution is `kaji-sdk`; Python code still uses `import kaji`, and
the installed CLI command is still `kaji`. The base install has no provider
deps. `kaji-sdk[openai]` adds the `openai` client,
`kaji-sdk[anthropic]` adds `anthropic`, `kaji-sdk[gemini]` adds
`google-genai`. The base SDK defaults to the mock provider for tests; choose
a real provider with `KAJI_MODEL_PROVIDER` or a scaffold generated by
`kaji init`. Python Kimi and the TypeScript Kimi/OpenRouter factories use
`OPENROUTER_API_KEY`.

Optional extras:

| Extra          | Adds                                           |
| -------------- | ---------------------------------------------- |
| `openai`       | `openai`                                       |
| `anthropic`    | `anthropic`                                    |
| `gemini`       | `google-genai`                                 |
| `providers`    | all of the above                               |
| `realtime`     | `redis` for experimental split event adapters  |
| `google-tools` | Google API clients for out-of-tree OAuth tools |
| `dev-ui`       | `rich` (for prettier CLI output)               |

## TypeScript

```bash
bun add kaji-sdk@0.2.0-beta.3 "zod@>=4.3 <5" openai
bun add kaji-sdk@0.2.0-beta.3 "zod@>=4.3 <5" @anthropic-ai/sdk # experimental/WIP
```

`zod >=4.3 <5` is a required peer dependency of `kaji-sdk`. `openai >=4 <8`
is the beta-supported optional peer. `@anthropic-ai/sdk >=0.30 <2` is an
optional peer for the experimental/WIP Anthropic adapter. Zod 3 and Zod 5 are
outside the supported beta range.

The no-key scaffold installs only the exact `kaji-sdk` version and supported
Zod range. OpenAI mode adds its beta-supported provider peer; Anthropic mode
adds the experimental/WIP peer.
Runtime support is Node 22 and 24; declarations compile with TypeScript 5.7.3
and current 6.x. npm and Bun are tested separately. pnpm and Yarn are not yet
claimed as supported package managers.

## CLI

Three packages expose a binary named `kaji`; their command sets are different.

```bash
pip install 'kaji-sdk==0.2.0b1' # Python SDK CLI: init/add/connect/disconnect/list/...
bun add kaji-sdk@0.2.0-beta.3 "zod@>=4.3 <5" # Embedded TS CLI: init/add/connect/disconnect/list/replay
```

The standalone cross-language `@kaji/cli` is not published yet and is outside
the SDK beta release. Its repository source includes `mcp`, which only reports
that server setup is deferred and does not write AI-tool config. See
[CLI](/docs/cli) for the exact command matrix and flag differences.

## Version policy

| Range   | Behavior                                                |
| ------- | ------------------------------------------------------- |
| `0.x.y` | pre-1.0. Minor bumps may rename or remove public names. |
| `>=1.0` | semver. Public surface is stable across minor versions. |

Pin exact versions in lockfiles until 1.0 lands. The events wire format
(field names + type strings) is stable across SDKs in 0.x.
