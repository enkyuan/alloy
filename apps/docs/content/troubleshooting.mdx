---
title: Troubleshooting
description: Diagnose common TypeScript and Python SDK setup, provider, tool, and event-history failures.
---

Start with the first error you can reproduce, then apply the matching fix.

## Cannot find package `kaji-sdk`

TypeScript `0.2.0-beta.10` is public on npm. Verify the exact version and then
install it with its required peer:

```bash
npm view kaji-sdk@0.2.0-beta.10 version
npm install kaji-sdk@0.2.0-beta.10 zod
```

If the first command returns `404`, check `npm config get registry`, your
proxy, and any corporate registry mirror before changing the package name or
version. Python remains unavailable from PyPI for this release.

## Cannot find package `openai`

The OpenAI adapter imports its optional peer only when selected. In a consumer
project that already has an installable Kaji artifact, add the OpenAI client
within the declared peer range:

```bash
npm install "openai@>=4 <8"
# or: bun add "openai@>=4 <8"
```

If you only use `MockProvider` from `kaji-sdk/testing`, you can omit `openai`.

## `OPENAI_API_KEY` is required

The `openai()` factory could not resolve a key from its options or
`OPENAI_API_KEY`, or `OpenAIProvider` received a blank explicit key. Export the
variable or load it from an ignored or encrypted environment file:

```bash
export OPENAI_API_KEY=sk-...
```

Generated TypeScript projects use dotenvx in their `start` script. The
Anthropic, OpenRouter, Kimi, and Gemini paths use their own documented keys and
remain WIP; they are not fallback credentials for OpenAI.

## Peer dependency version mismatch

The declared ranges are `zod >=4.3 <5` and `openai >=4 <8`. Zod is required;
OpenAI is optional. The WIP Anthropic adapter, whose machine tier is
`experimental`, separately declares `@anthropic-ai/sdk >=0.30 <2`. Upgrade or
pin the conflicting workspace dependency to a declared range.

## `MISSING_TOOL_IDENTITY` or unclassified tool risk

Every enabled tool needs an explicit risk classification. Every turn that can
execute a tool needs a caller principal:

```ts
await runtime.turn("Run the tool", {
  context: { principalId: "my-app" },
});
```

Do not hardcode a shared principal inside a handler. Text-only runtimes may
omit identity.

## Tool calls never fire

Check these boundaries in order:

1. Pass the result of `functionTool(...)` to `AgentBuilder().tool(...)`. The
   global `registerTool(...)` function returns `void` and writes to the default
   registry; it does not bind a tool to the builder's scoped registry.
2. Confirm the selected provider API supports function calling.
3. Make the tool description and parameter schema specific enough for the
   model to select it.

## Event history is empty after a turn

`runtime.history(sessionId)` reads from the `EventStore` supplied to the
runtime, or its default `InMemoryEventStore`. Reuse the same store between the
turn and the read. Page with `afterSequence`; persisted sequence, not
timestamp, defines order.

To consume events as they are committed, subscribe through the committer. See
[event delivery](/docs/concepts/event-bus).

## Provider request failed

Catch `ProviderError` from the package root and normalize it:

```ts
import { normalizeProviderError, ProviderError } from "kaji-sdk";

try {
  await runtime.turn("Hello");
} catch (error) {
  if (error instanceof ProviderError) {
    const failure = normalizeProviderError(error);
    console.error(failure.code, failure.retryable);
  }
}
```

The normalized fields are safe for routing and retry policy. Do not log vendor
exceptions, response bodies, causes, prompts, credentials, headers, or tool
arguments.

## Python SDK issues

### `ModuleNotFoundError: No module named 'openai'`

The Python distribution is unavailable from PyPI for this release. In a source
checkout, install the provider extra through the project environment:

```bash
uv sync --project kaji --extra openai
```

### Control top-level import loading

The top-level package uses PEP 562 lazy loading. First access to a symbol
imports its submodule. Import a specific name from its public subpackage when
you need to control that first-access cost.

### `kaji` is not on `PATH` after source setup

Run the CLI through the project environment:

```bash
uv run --project kaji kaji --help
```
