The TypeScript package declares a `kaji` binary, but its npm package remains
unavailable until protected registry-byte verification succeeds. Run it from
the source checkout. The Python SDK and WIP standalone package use the same
binary name, but their command sets differ.

| ------------------- | :-------------------: | :----------------------------: | :-----------------------------: |

| `add`               |          Yes          |              Yes               |               No                |

## TypeScript SDK CLI

From the repository root, invoke the embedded CLI source to scaffold TypeScript
projects, manage the packaged registry, and render stored event logs:

```bash
bun kaji/ts/src/cli/bin.ts init ./my-agent --provider mock --yes
bun kaji/ts/src/cli/bin.ts list-integrations
bun kaji/ts/src/cli/bin.ts add echo --out ./integrations/echo
bun kaji/ts/src/cli/bin.ts add github --out ./integrations/github --allow-experimental
bun kaji/ts/src/cli/bin.ts connect <oauth-integration> --principal <stable-host-principal-id>
bun kaji/ts/src/cli/bin.ts disconnect <oauth-integration> --principal <stable-host-principal-id>
bun kaji/ts/src/cli/bin.ts replay ./session.jsonl --format summary
```

`init` takes a positional destination and accepts `--provider`, `--yes`, and
`--force`. `init` does not accept `--out`; `add` uses `--out` for its exact
destination.

Generated projects pin dotenvx and `kaji-sdk@0.2.0-beta.10`. Until protected
publication completes, scaffold inspection is source-only; installing that
dependency through npm or Bun will return `404`. Experimental-registry
integrations require `--allow-experimental`.

`connect` and `disconnect` are available for integrations whose manifest
declares OAuth. No such integration ships in the 0.2 catalog. `replay`
supports `tree`, `summary`, and `json`, plus optional `--filter`, `--grep`, and
`--tail` arguments.

The TypeScript SDK CLI accepts global `--no-color` and `--verbose` flags before
the command. Successful data uses stdout; diagnostics use stderr.

| Exit | Meaning                                                                     |
| ---: | --------------------------------------------------------------------------- |
|  `0` | Success, help, or an `add --check` result that is current                   |
|  `1` | Validation, runtime, file, or copy failure                                  |
|  `2` | Malformed usage                                                             |
|  `3` | `add --check`: bundle is absent                                             |
|  `4` | `add --check`: bundle is outdated                                           |
|  `5` | `add --check`: bundle has local modifications or another ownership conflict |
|  `6` | `add --check`: bundle is demoted and cannot be promoted automatically       |

Codes `3` through `6` classify copied bundle state; they are not generic
runtime failures. Replay output is a closed, redaction-safe projection.

## Python SDK CLI

The Python distribution is not available from PyPI for this release. From a
source checkout, its `kaji` CLI scaffolds Python projects, generates Python or
TypeScript OpenAPI handlers, and manages the Python registry:

```bash
uv run --project kaji kaji init ./my-agent --provider mock --yes
uv run --project kaji kaji gen --spec openapi.json --out tools/ --lang python
uv run --project kaji kaji list-integrations
uv run --project kaji kaji add echo --out ./integrations
uv run --project kaji kaji info --json
uv run --project kaji kaji doctor
```

Its `init` writes `agent.py` and `.env.example`. The `gen`, `info`, `secret`,
`doctor`, and `upgrade` commands are WIP; their machine contract tier is
`experimental`.

## Standalone cross-language CLI

`@kaji/cli` is not available from npm. Contributors can run its WIP source when
evaluating a single scaffold and diagnostic tool for both languages:

```bash
bun apps/cli/src/index.ts --help
```

Its repository version is `0.1.0`. It provides `init`, `gen`, `info`, `secret`,
`doctor`, `upgrade`, and `mcp`. The `mcp` command reports that no server is
available; it does not install a server or write AI-tool configuration.

Avoid relying on whichever `kaji` binary wins package-manager linking when
multiple Kaji packages are installed. Invoke the intended package from a
package script or with an explicit package runner.
