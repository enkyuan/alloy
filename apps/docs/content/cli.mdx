The local TypeScript alpha candidate declares a `kaji` binary. Install the
`irogane-kaji-0.3.0-alpha.1.tgz` artifact in your project, then invoke that local binary through
your package manager. The Python SDK and WIP standalone package use the same
binary name, but their command sets differ.

## Command surfaces

| Command             |  TypeScript `kaji`  | Python `kaji` distribution |     Standalone `@irogane/kaji/cli`      |
| ------------------- | :-----------------: | :------------------------: | :-------------------------------------: |
| `init`              | TypeScript scaffold |      Python scaffold       | TypeScript scaffold; Python unavailable |
| `add`               |         No          |            Yes             |                   No                    |
| `connect`           |         No          |            Yes             |                   No                    |
| `disconnect`        |         No          |            Yes             |                   No                    |
| `list-integrations` |         No          |            Yes             |                   No                    |
| `replay`            |         Yes         |             No             |                   No                    |
| `gen`               |         No          | WIP (`experimental` tier)  |        WIP (`experimental` tier)        |
| `info`              |         No          | WIP (`experimental` tier)  |        WIP (`experimental` tier)        |
| `secret`            |         No          | WIP (`experimental` tier)  |        WIP (`experimental` tier)        |
| `doctor`            |         No          | WIP (`experimental` tier)  |        WIP (`experimental` tier)        |
| `upgrade`           |         No          | WIP (`experimental` tier)  |        WIP (`experimental` tier)        |
| `mcp`               |         No          |             No             |     WIP; no server or config writer     |

Use the selected package's `--help` output as the exact flag reference.

## TypeScript SDK CLI

Install the local alpha artifact, then use its embedded CLI to scaffold
capability projects and render stored event logs:

```bash
npm install ./irogane-kaji-0.3.0-alpha.1.tgz zod
npm exec -- kaji init ./my-capability --yes
npm exec -- kaji replay ./session.jsonl --format summary
```

`init` takes a positional destination and accepts `--template capability`,
`--yes`, and `--force`. The capability template has no agent or provider
imports; registry management commands live in the Python CLI.

Generated projects pin dotenvx and `@irogane/kaji@0.3.0-alpha.1`; provide the local
tarball when installing the generated project.

`replay` supports `tree`, `summary`, and `json`, plus optional `--filter`,
`--grep`, and `--tail` arguments.

The TypeScript SDK CLI accepts global `--no-color` and `--verbose` flags before
the command. Successful data uses stdout; diagnostics use stderr.

| Exit | Meaning                                        |
| ---: | ---------------------------------------------- |
|  `0` | Success or help                                |
|  `1` | Validation, runtime, or file failure           |
|  `2` | Malformed usage                                |

Replay output is a closed, redaction-safe projection.

## Python SDK CLI

The Python distribution is not available from PyPI for this release. From a
source checkout, its `kaji` CLI scaffolds Python projects, generates Python or
TypeScript OpenAPI handlers, and manages the Python registry:

```bash
uv run --project kaji/packages/py kaji init ./my-agent --provider mock --yes
uv run --project kaji/packages/py kaji gen --spec openapi.json --out tools/ --lang python
uv run --project kaji/packages/py kaji list-integrations
uv run --project kaji/packages/py kaji add echo --out ./integrations
uv run --project kaji/packages/py kaji info --json
uv run --project kaji/packages/py kaji doctor
```

Its `init` writes `agent.py` and `.env.example`. `init` does not accept `--out`;
`add` uses `--out` for its exact destination. The `gen`, `info`, `secret`,
`doctor`, and `upgrade` commands are WIP; their machine contract tier is
`experimental`.

| Exit | Meaning                                                                     |
| ---: | --------------------------------------------------------------------------- |
|  `0` | Success, help, or an `add --check` result that is current                   |
|  `1` | Validation, runtime, file, or copy failure                                  |
|  `2` | Malformed usage                                                             |
|  `3` | `add --check`: bundle is absent                                             |
|  `4` | `add --check`: bundle is outdated                                           |
|  `5` | `add --check`: bundle has local modifications or another ownership conflict |
|  `6` | `add --check`: bundle is demoted and cannot be promoted automatically       |

Codes `3` through `6` classify copied bundle state; they are not generic
runtime failures.

## Standalone cross-language CLI

`@irogane/kaji/cli` is not available from npm. Contributors can run its WIP source when
evaluating a single scaffold and diagnostic tool for both languages:

```bash
bun apps/cli/src/index.ts --help
```

Its repository version is `0.1.0`. Its `init` command scaffolds TypeScript only:
Python initialization fails closed because Kaji Python is not published to PyPI.
Use the [Python source-checkout install route](https://github.com/enkyuan/alloy/blob/main/kaji/packages/py/README.md#install)
instead. It provides `gen`, `info`, `secret`, `doctor`, `upgrade`, and `mcp`.
The `mcp` command reports that no server is available; it does not install a
server or write AI-tool configuration.

Avoid relying on whichever `kaji` binary wins package-manager linking when
multiple Kaji packages are installed. Invoke the intended package from a
package script or with an explicit package runner.
