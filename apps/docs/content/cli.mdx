Kaji has three binaries named `kaji`. They are separate packages with separate
command sets. Install the one that owns the workflow you need, and use its
`--help` output as the exact flag reference.

## Command surfaces

| Command             | Python `kaji-sdk` distribution | Embedded `@kaji/sdk` |         Standalone `@kaji/cli`          |
| ------------------- | :----------------------------: | :------------------: | :-------------------------------------: |
| `init`              |        Python scaffold         | TypeScript scaffold  |      Python or TypeScript scaffold      |
| `add`               |              Yes               |         Yes          |                   No                    |
| `connect`           |              Yes               |         Yes          |                   No                    |
| `disconnect`        |              Yes               |         Yes          |                   No                    |
| `list-integrations` |              Yes               |         Yes          |                   No                    |
| `replay`            |               No               |         Yes          |                   No                    |
| `gen`               |          Experimental          |          No          |              Experimental               |
| `info`              |          Experimental          |          No          |              Experimental               |
| `secret`            |          Experimental          |          No          |              Experimental               |
| `doctor`            |          Experimental          |          No          |              Experimental               |
| `upgrade`           |          Experimental          |          No          |              Experimental               |
| `mcp`               |               No               |          No          | Status only; no server or config writer |

## Python SDK CLI

`pip install kaji-sdk` installs the Python SDK and its `kaji` CLI. It scaffolds Python
projects, generates Python or TypeScript OpenAPI handlers, and manages the
packaged integration registry.

```bash
kaji init ./my-agent --provider mock --yes
kaji gen --spec openapi.yaml --out tools/ --lang python
kaji list-integrations
kaji add echo --out ./integrations
kaji add github --out ./integrations --allow-experimental
kaji info --json
kaji doctor
```

`init` takes the destination as a positional path. It writes `agent.py` and
`.env.example`. Use `--force` to overwrite. `add` copies integration source so
the application owns it; inspect the manifest's risk and auth requirements
before enabling the copied tools. `connect` and `disconnect` manage grants only
for integrations whose manifest declares OAuth; no such integration is bundled
in the current catalog.

## Embedded TypeScript SDK CLI

Installing `@kaji/sdk` exposes a small CLI for the packaged TypeScript registry
and replay tooling. It is not the standalone scaffold/diagnostics package.

```bash
kaji init ./my-agent --provider mock --yes
kaji list-integrations
kaji add echo --out ./integrations
kaji add github --out ./integrations --allow-experimental
kaji connect <oauth-integration> --principal <stable-host-principal-id>
kaji disconnect <oauth-integration> --principal <stable-host-principal-id>
kaji replay ./session.jsonl --format summary
```

The embedded `init` uses the same positional path, provider, `--yes`, and
`--force` grammar as Python. TypeScript temporarily accepts deprecated `--out`
with one stderr warning, but maintained examples use the positional path.
Experimental integrations require `--allow-experimental`. The auth commands
are present for manifest-declared OAuth integrations, but Gmail tools and a
Gmail manifest are not shipped at this checkpoint. `replay` accepts
`tree`, `summary`, or `json` output plus optional `--filter`, `--grep`, and
`--tail` arguments.

Both embedded SDK CLIs accept global `--no-color` and `--verbose` before the
command. Successful data uses stdout, diagnostics use stderr, and exits are 0
for success/help, 1 for validation/runtime/file conflicts, and 2 for usage.
Replay output is a closed redaction-safe projection.

## Standalone cross-language CLI

Install `@kaji/cli` when you want one scaffold and diagnostic tool for either
language:

```bash
bun add -D @kaji/cli
bunx @kaji/cli init --cwd ./my-agent --lang ts --provider openai --yes
bunx @kaji/cli gen --spec openapi.yaml --out tools/ --lang ts
bunx @kaji/cli info --json
bunx @kaji/cli doctor
```

It provides `init`, `gen`, `info`, `secret`, `doctor`, `upgrade`, and `mcp`.
Its `init` uses `--cwd` and requires an explicit `--lang` for non-interactive
cross-language scaffolding. The `mcp` command only reports that server support
is deferred; it does not install a server or write AI-tool configuration.

The published standalone package remains `0.1.x`; the next CLI changes in this
repository are unreleased and outside the SDK beta-core compatibility promise.

If both npm packages are present, avoid relying on whichever `kaji` bin wins
package-manager linking. Invoke the standalone package explicitly (for example,
`bunx @kaji/cli --help`) or run the embedded SDK binary from its package script.
